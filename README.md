# إدارة البرج — Vercel-only deployment

مشروع عربي لإدارة الاستاف والمهمات، مصمم للنشر كمشروع واحد على Vercel. يستخدم Vercel Functions للـAPI، وPostgreSQL متصلًا من Vercel Marketplace للبيانات الدائمة، وVercel Blob **Private Store** لملفات الأدلة. لا يحتاج إلى Render أو خادم Node دائم.

> **مهم:** لأن Vercel Functions ليست اتصال Discord Gateway دائمًا، يستعمل هذا الإصدار Discord REST API. إنشاء المهمات من الموقع ينشرها إلى روم المهمات، وعند فتح/تحديث تبويب المهمات يراجع الموقع أحدث رسائل الروم لاستيراد المهمات المكتوبة بتنسيق مدعوم. لا يمكن لهذا الإصدار ضمان اكتشاف فوري لكل رسالة Discord لحظة إرسالها، مثل بوت يعمل باتصال Gateway مستمر.

## 1) ارفع المشروع إلى GitHub

1. حمّل ملف ZIP وفك ضغطه.
2. أنشئ مستودعًا جديدًا في GitHub، ويفضّل Private.
3. ارفع **محتويات هذا المجلد مباشرة** إلى جذر المستودع؛ يجب أن تظهر `api/` و`site-src/` و`package.json` في صفحة المستودع الرئيسية.
4. لا ترفع `.env` أو أي توكن/سر. ملف `.env.example` مجرد مثال ولا يحتوي على أسرار فعلية.

## 2) أنشئ مشروع Vercel

1. افتح https://vercel.com/new وسجّل الدخول باستخدام GitHub.
2. اضغط Import على المستودع.
3. اترك **Root Directory** على الجذر (`./`) ولا تختَر مجلدًا فرعيًا.
4. Framework Preset: `Other`.
5. Build Command: `npm run build`.
6. Output Directory: `dist`.
7. Install Command: `npm install`.
8. اضغط Deploy. قد يفشل جزء من وظائف الموقع في أول نشر حتى تضيف متغيرات البيئة وقاعدة البيانات والتخزين في الخطوات التالية؛ أعد النشر بعدها.

## 3) أضف قاعدة PostgreSQL من داخل Vercel

1. افتح مشروعك في Vercel ثم صفحة **Storage** أو **Marketplace** (قد يختلف اسمها قليلًا حسب واجهة الحساب).
2. أضف تكامل PostgreSQL مثل Neon من Vercel Marketplace، ثم اربطه بهذا المشروع.
3. وافق على إضافة متغير الاتصال إلى المشروع. الكود يتعرف على `DATABASE_URL` أو `POSTGRES_URL` أو `POSTGRES_URL_NON_POOLING` أو `DATABASE_URL_UNPOOLED` أو `POSTGRES_PRISMA_URL`.
4. لا تنشئ قاعدة SQLite؛ بيانات SQLite المحلية ليست مناسبة لتشغيل Serverless على Vercel.

## 4) أنشئ تخزين الأدلة الخاص

1. من صفحة Storage للمشروع، اختر إنشاء Blob Store.
2. اختر **Private** وليس Public؛ الأدلة قد تتضمن مواد داخلية للاستاف.
3. اربط الـBlob Store بالمشروع واختر بيئات Production وPreview التي تحتاجها.
4. يجب أن يظهر متغير `BLOB_READ_WRITE_TOKEN` في Environment Variables. لا تكشفه في الواجهة ولا تضعه في `site-src/`.
5. الواجهة ترفع الصور والفيديوهات مباشرة إلى Blob، لذلك لا تمر الملفات الكبيرة عبر حجم طلب الـFunction.

## 6) أعد توجيه OAuth في Discord

1. افتح https://discord.com/developers/applications واختر التطبيق الصحيح.
2. اذهب إلى OAuth2 وأضف الرابط نفسه الموجود في `DISCORD_REDIRECT_URI` إلى Redirects.
3. تأكد أن الـClient Secret في Vercel من نفس التطبيق.
4. في قسم Bot، فعّل **Server Members Intent** إذا لم تكن مفعّلة، حتى يتمكن الموقع من جلب أعضاء سيرفر الاستاف وقائمة الرتب.
5. تأكد أن البوت موجود في سيرفر الاستاف والسيرفر الأساسي، ولديه صلاحيات عرض القنوات وقراءة/إرسال الرسائل في روم المهمات وروم التسليم.
6. لأنه يستخدم REST API بدل Gateway، لا يحتاج إلى تشغيل عملية `client.login()` أو خادم دائم. وقد لا يعرض Discord حالة Presence كـOnline؛ المهم أن طلبات API وصلاحيات القنوات تعمل.

## 7) أعد النشر واختبر

1. ارجع إلى Vercel → Deployments → اختر آخر Deployment → Redeploy.
2. افتح رابط الموقع، واضغط تسجيل الدخول بديسكورد.
3. اختبر قائمة الاستاف، إنشاء مهمة إجباريّة/اختيارية، إرسال تسليم بصورة أو فيديو، وروم التسليم، ثم جرّب الشاتين.
4. إذا ظهر خطأ، افتح Vercel → Functions/Logs وشاهد سبب الخطأ. لا تنسخ التوكن أو Client Secret في الشات.

## ما الذي يعمل وكيف تتم المزامنة؟

- تسجيل دخول Discord OAuth2، مع صلاحيات الاستاف/الإدارة.
- قائمة أعضاء سيرفر الاستاف مجمعة حسب أعلى رتبة لهم في السيرفر الأساسي.
- شات الاستاف، وشات إدارة خاص بالمسؤولين المحددين أو الحسابات التي تملك صلاحية Administrator.
- نشر عدة مهمات في رسالة أو أكثر حسب طول الرسالة، مع نوع إجباري/اختياري.
- تسليم مهمة أو مجموعة مهمات مع روابط أو ملفات صور/فيديو.
- تُحفظ البيانات في PostgreSQL، وتُحفظ الأدلة في Private Blob.
- ملفات الأدلة الخاصة تُخدم عبر Function بعد التحقق من رمز وصول عشوائي مخزن مع التسليم؛ رابط الدليل يعمل لمن يمتلكه، فتعامل معه كرابط خاص ولا تنشره خارج الاستاف.

**القيد الوحيد المتعلق بطريقة عمل البوت:** لا يوجد اتصال Gateway دائم في هذا النشر؛ استيراد الرسائل العادية من روم المهمات يحصل عندما يراجع الموقع أحدث الرسائل، وليس لحظة إرسال الرسالة بشكل مضمون. إنشاء المهمات من داخل الموقع ينشرها ويحفظها مباشرة، وهو المسار الموصى به لهذا الإصدار.


## نظام النقاط ومراجعة المهمات

- لكل مهمة حقل نقاط مستقل يقبل `0` أو كسورًا حتى منزلتين عشريتين مثل `0.1` و`0.25`. يمكن تعديل النقاط أثناء تجهيز قائمة النشر أو لاحقًا من صف المهمة نفسها، ويُحفظ التعديل مباشرة في قاعدة البيانات.
- التسليمات تبدأ بحالة «بانتظار الموافقة». من سجل التسليمات في الموقع يستطيع المسؤول اعتماد التسليم أو رفضه؛ لا تُمنح نقاط المهمة إلا بعد الاعتماد، والاعتماد لا يتكرر للتسليم نفسه.
- إضافة/خصم النقاط يدويًا متاحة للمسؤولين من قسم إدارة المهمات، باستخدام Discord ID للعضو، وقيمة موجبة للإضافة أو سالبة للخصم.
- تُرسل سجلات إضافة/خصم النقاط واعتماد التسليم إلى الروم `1559598706871767172` في Embed منسق، يشمل العضو، مقدار التغيير، الرصيد الحالي/بعد الاعتماد، السبب أو المهمات، المسؤول، والوقت. وتُنشر أدلة المهمات المختارة مع اسم المهمة والعضو والملفات/الروابط في Embed منسق داخل الروم `1556945732957765722`، وهذا المعرّف مثبت في الكود لضمان وصول الدليل إلى الروم المطلوبة.
- يمكن تغيير الرومين عبر متغيري البيئة `POINTS_LOG_CHANNEL_ID` و`SUBMISSION_REVIEW_CHANNEL_ID`.
- قاعدة بيانات PostgreSQL تُحدّث تلقائيًا عند تشغيل API؛ تُضاف أعمدة النقاط ومراجعة التسليمات والجداول اللازمة دون حذف البيانات القديمة.

### Explicit nested API routes

To improve compatibility with Vercel route resolution, the project includes dedicated wrappers for `/api/tasks/:id`, `/api/chat/:room`, `/api/submissions/:id/:action`, and `/api/staff-requests/:id/:action`. They forward requests to the shared API handler and do not require a separate backend service.


## إحصائيات الإدارة والطلبات الإدارية
تعرض الصفحة الرئيسية ملخصات المسؤولين، والضغط على اسم عضو من القائمة الجانبية يفتح ملفه الكامل. يستطيع عضو الاستاف إرسال طلب إجازة أو طلب إداري آخر (إذن/غياب، مشكلة تقنية، تعديل بيانات، شكوى/ملاحظة، أو طلب آخر). تصل طلبات الإجازة ومراجعاتها إلى الروم `1556945732957765722`، بينما تصل جميع الطلبات الإدارية الأخرى (الإذن/الغياب، المشكلة التقنية، تعديل البيانات، الشكوى، والطلبات الأخرى) وكذلك إشعارات قبولها ورفضها إلى الروم `1560142058826768425`. معرّف روم الطلبات الإدارية مثبت في الكود، ولا يغيّر مسار الإجازات. يمكن لمسؤولي الإدارة قبول الطلبات أو رفضها من لوحة الموقع. الموافقة على طلب عادي لا تغيّر رتب Discord؛ الرتبتان المعرّفتان في إعدادات الموقع تُستخدمان لتحديد صلاحيات الإدارة فقط.

ملاحظة: روم طلبات الإجازة ومراجعتها مثبت على `1556945732957765722` في الكود. بعد تحديث الملفات أعد نشر الموقع؛ لا تحتاج إلى ضبط `LEAVE_REQUEST_CHANNEL_ID`.


## قبول ورفض طلبات الإجازة من الموقع أو ديسكورد
- تظهر زرا **قبول الإجازة** و**رفض الإجازة** مع رسالة الطلب في روم `1556945732957765722`.
- الضغط من الموقع أو من ديسكورد يحدّث حالة الطلب نفسها في PostgreSQL، ويعدّل رسالة ديسكورد الأصلية ويزيل أزرارها بعد حسم الطلب.
- بعد إضافة `DISCORD_PUBLIC_KEY` إلى Environment Variables، افتح Discord Developer Portal → تطبيق البوت → **General Information**، وانسخ **Public Key** إلى المتغير السابق.
- في صفحة **Interactions Endpoint URL**، ضع `https://رابط-موقعك/api/discord-interactions` ثم احفظ التغيير. استبدل رابط المثال بالدومين الفعلي للموقع. Discord سيختبر الـ endpoint عبر PING؛ يجب أن تكون النسخة منشورة والمتغير مضبوطًا قبل الحفظ.
- صلاحية المراجعة للمسؤولين المحددين في `MANAGER_IDS`، أو من لديهم صلاحية Administrator أو رتبة الإدارة المعرفة في `MANAGEMENT_MAIN_ROLE_ID` / `MANAGEMENT_STAFF_ROLE_ID`.
- بعد التغيير اعمل Redeploy، ثم سجّل الخروج من الموقع وادخل من جديد حتى تتحدث صلاحيات الجلسة. جرّب طلب إجازة جديد؛ الطلبات القديمة التي لم يُسجل لها Discord message ID ستظل قابلة للمراجعة من الموقع، لكن لا يمكن ربط الأزرار برسائلها القديمة.

## رتب الإجازة التلقائية
- عند قبول الإجازة (من الزر أو الموقع) يعطي البوت الرتبة في السيرفرين لو الإجازة سارية اليوم (بتوقيت القاهرة)، وإلا تُعطى في أول يوم إجازة.
- مهمة يومية مجانية (`crons` في `vercel.json` → `/api/cron/leave-sync`) تعطي الرتب لمن بدأت إجازتهم، وتسحبها ممن انتهت إجازتهم، وتنشر تقرير الإجازات اليومي في روم الإجازات.
- أضف في Vercel المتغير `CRON_SECRET` (أي نص عشوائي طويل)؛ Vercel يرسله تلقائيًا مع المهمة.
- الرتب: `LEAVE_ROLE_MAIN_ID` و`LEAVE_ROLE_STAFF_ID` (الافتراضي: رتبتا الإدارة المحددتان). البوت يحتاج صلاحية Manage Roles ورتبته أعلى من هذه الرتب.
- لا تُسحب الرتبة إلا إذا كان البوت هو من أعطاها.

## مهلة المهمات، بصمة الصور، وسجل قرارات التسليم

- عند تجهيز كل مهمة يمكن تحديد موعد انتهاء من حقل **مهلة المهمة**. بعد انتهاء الموعد تُغلق المهمة تلقائيًا ولا تظهر كمهمة قابلة للتسليم، حتى لو لم يعمل المجدول في نفس اللحظة.
- مجدول `/api/cron/task-deadlines` يرسل تذكيرًا خاصًا للأعضاء المعروفين للنظام عندما تقترب المهمة من الانتهاء خلال 24 ساعة، ويغلق المهمات المنتهية. تمت إضافته بتشغيل يومي حتى يظل النشر متوافقًا مع Vercel Hobby؛ لذلك توقيت التذكير قد يتأخر عن 24 ساعة ببعض الوقت. إذا كنت تحتاج فحصًا كل ساعة بدقة، استخدم Vercel Pro أو خدمة جدولة خارجية تستدعي المسار نفسه مع `Authorization: Bearer <CRON_SECRET>`. أضف `CRON_SECRET` إلى Environment Variables.
- الصور الجديدة يتم حساب بصمتها SHA-256 وتسجيلها. لو ظهرت الصورة نفسها في تسليم سابق، يظهر تحذير واضح داخل Embed ديسكورد وفي قائمة التسليمات للمسؤولين مع أرقام التسليمات وأسماء أصحابها؛ التحذير لا يمنع الموافقة تلقائيًا. الصور القديمة تُفحص على دفعات صغيرة بواسطة المجدول.
- رسائل الأدلة المنشورة في روم `1556945732957765722` تحتوي زري **موافقة وإضافة النقاط** و**رفض التسليم**. الرفض يفتح نموذجًا اختياريًا لكتابة السبب. يُسجّل القرار مع اسم/ID المراجع ووقت القرار، وتُزال الأزرار بعد إتمام المراجعة لمنع تكرارها. يجب أن يكون `DISCORD_PUBLIC_KEY` مضبوطًا في Vercel وأن تكون قيمة Interactions Endpoint URL هي `https://رابط-موقعك/api/discord-interactions`.
- معالجة أزرار الموافقة والرفض موجودة الآن في `api/discord-interactions.js` لوضع HTTP، وكذلك في `bot-worker/index.js` لوضع Gateway. Discord يختار طريقة استقبال تفاعلات واحدة فقط: عند ضبط Interactions Endpoint URL تُرسل التفاعلات إلى HTTP؛ وعند تركه فارغًا تُرسل إلى Gateway. لو تستخدم وضع Gateway، أعد نشر `bot-worker/` بعد التحديث وشغّله باستمرار.
- إصلاح v30: أزرار التسليم تستخدم الآن نفس نمط أزرار الإجازات؛ يتم تسجيل القرار وإضافة النقاط بشكل ذري قبل الرد متى أمكن، ومعالجة التأخير بتأكيد احتياطي ثم تحديث الرسالة. عند استمرار المشكلة افتح `https://رابط-موقعك/api/discord-interactions` وتأكد أن `publicKeySet` و`botTokenSet` و`databaseSet` كلها `true`، وأن Interactions Endpoint URL في Discord يطابق هذا المسار تمامًا. النشر الموصى به يكون من جذر المستودع `./` وليس من `vercel-frontend/`.
- قسم **إحصائيات المهمات والتسليمات** في صفحة المهمات يعرض إجمالي التسليمات، المقبول والمرفوض والمعلّق، أكثر الأعضاء تسليمًا، ومن لم يسلّم منذ 14 يومًا أو لم يسلّم من قبل. ويمكن تصدير سجل قرارات الأدمن إلى CSV بترميز مناسب لبرنامج Excel.

## Vercel setup
`vercel.json` uses explicit `builds` so only `api/handler.js` and `api/discord-interactions.js` become Functions (2 total, far under the Hobby limit of 12) no matter what other files exist in the repo.

- إشعار القبول/الرفض يُرسل إلى الروم `1558102515885678734` (أو `LEAVE_NOTICE_CHANNEL_ID`) مع السبب إن وُجد. زر الرفض في ديسكورد يفتح نافذة لكتابة السبب.

## أمر «نقاطي» بدون بريفكس

العضو يكتب `نقاطي` (أو `mypoints`) كرسالة عادية والبوت يرد عليه بنقاطه.

- **لو بتشغّل `server.js`** (اتصال Gateway دائم): الأمر شغال تلقائيًا.
- **لو على Vercel**: Vercel Functions مش بتقدر تسمع رسائل عادية، فشغّل مجلد `bot-worker/` على استضافة Node دائمة (Railway / Render / VPS) بالمتغيرين `DISCORD_BOT_TOKEN` و`DATABASE_URL` (نفس قاعدة بيانات الموقع)، بالأمر `npm install && npm start`.
- في الحالتين لازم تفعّل **Message Content Intent** من Discord Developer Portal ← Bot ← Privileged Gateway Intents.
- الرد بيكون في نفس الروم (رسائل ديسكورد العادية مفيش فيها رد خاص زي الـslash). الأمر السلاش الوحيد هو `/mypoints` (بيتسجل تلقائيًا).

## تحديثات v21 — خصوصية، أداء، إشعارات، وتصدير CSV

**الخصوصية**
- `/api/staff-stats`: العضو العادي يشوف فقط الحقول العامة للّيدر بورد (النقاط، الرسائل، التسليمات المقبولة، متصل/لا). أرقام التسليمات المعلّقة/المرفوضة والإجازات والطلبات الإدارية وآخر ظهور للمسؤولين فقط.
- `/api/staff-stats/:id`: السجل التفصيلي (حركات النقاط، التسليمات، الإجازات، الطلبات الإدارية) لصاحب الحساب والمسؤولين فقط، والرد فيه `restricted: true` لغيرهم.
- `/api/roster`: تواريخ دخول السيرفرات للمسؤولين فقط. قسم «إحصائيات المسؤولين» في الرئيسية صار للمسؤولين فقط.
- `/api/health` العام لا يكشف رسالة خطأ البوت لغير المسؤولين.

**تخفيف الضغط**
- كاش في الذاكرة مع دمج الطلبات المتزامنة وإرجاع آخر نسخة عند فشل Discord: الروستر (دقيقتان)، الإحصائيات (15ث)، الحضور (10ث)، فحص البوت (دقيقة).
- `ensureSchema` استعلام واحد في الـcold start بدل ~40 (جدول `app_meta`). ارفع `SCHEMA_VERSION` عند إضافة جداول جديدة. أُضيفت فهارس للحالات وللبحث في ملفات الأدلة.
- الشات يستعلم بـ`?after=<آخر id>` فيرجع الجديد فقط، بدون مزامنة Discord، كل 6 ثوانٍ، ويتوقف والتبويب مخفي. نبضة الحضور كل 60ث وتكتب في الداتابيز عند الحاجة فقط.
- حد طلبات لكل مستخدم على المسارات الثقيلة (يرجع `429` مع `Retry-After`). مزامنة رسائل Discord بحد أدنى 45ث (`MESSAGE_SYNC_MIN_SECONDS`).

**إشعار خاص (DM)** للعضو عند قبول/رفض: التسليم، الإجازة (من الموقع أو من أزرار Discord)، والطلب الإداري. لو الخاص مقفول تكتمل المراجعة عادي ويظهر للمسؤول تنبيه بذلك.

**إشعارات داخل الموقع للمسؤولين**: جرس بعدّاد غير المقروء عند وصول تسليم/إجازة/طلب إداري جديد، يفتح القسم المرتبط، ويحدّث القوائم تلقائيًا. الجدولان: `admin_notifications` و`admin_notification_reads`.

**أمر `/csv`** (للمسؤولين فقط، ردّه مخفي): يرفق ملف CSV بترميز UTF-8 يفتح مباشرة في Excel. الخيارات: ملخص الاستاف (الافتراضي)، التسليمات، الإجازات، سجل النقاط، الطلبات الإدارية، وسجل قرارات مراجعة التسليمات. الأمر يُسجَّل تلقائيًا، أو افتح `/api/register-commands` مرة بعد النشر. الصلاحية: `MANAGER_IDS` أو Administrator/رتبة الإدارة داخل السيرفر الأساسي أو سيرفر الاستاف فقط.

> بعد رفع هذا الإصدار شغّل `npm install` (أُضيفت `@vercel/functions`) وأعد النشر.

## توحيد إشعارات قبول ورفض التسليم — v31
- قالب واحد مشترك (`lib/submission-notifications.js`) يُستخدم عند القرار من الموقع أو من أزرار ديسكورد، سواء استقبال التفاعل عبر HTTP أو Gateway أو تشغيل `server.js` محليًا.
- رسالة القبول/الرفض في روم إعلانات إنجاز المهمات أصبحت موحدة: اسم المهمة، العضو الذي سلّمها، المسؤول الذي راجعها، مقدار النقاط، الرصيد الحالي، وسبب الرفض إن وجد. القبول يعرض الدليل المرفق عند اختياره من الموقع.
- سجل النقاط في `1559598706871767172` يستخدم نفس Embed في جميع مسارات المراجعة، ويحتوي تفاصيل المهمات ومجموع النقاط والرصيد بعد القرار.
- روم إعلان القرار هو `TASK_APPROVED_CHANNEL_ID`، أو `TASK_SUBMISSIONS_CHANNEL_ID` عند عدم ضبط الأول، وافتراضيًا `1556651404154642504`. لتغيير الروم اضبط `TASK_APPROVED_CHANNEL_ID` في Vercel وفي استضافة `bot-worker`/السيرفر المحلي إن كنت تستخدمها.
- بعد تحديث الملفات، أعد نشر Vercel. إذا كنت تستخدم `bot-worker` على Railway/Render أو `server.js` محليًا، حدّثه وأعد تشغيله أيضًا حتى يستخدم قالب الإشعار نفسه.
